# SSIM — Santer Steam Inventory Manager

Multi-account CS2 inventory, trading & market tool. The desktop app is ONE self-contained
**SSIM.exe** — a **Tauri shell** (Rust) with the **Node backend** (the real app) embedded inside it;
on launch the shell self-extracts the backend to `runtime\` and spawns it as a hidden child.

## Repo map
| Path | What it is |
|---|---|
| `src/` | **Node backend** (TypeScript) — the actual app: Steam sessions, trading, market, licensing |
| `src-tauri/` | **Tauri desktop shell** (Rust). Native window + spawns/monitors the backend sidecar — see `src/lib.rs` |
| `public/` | Dashboard frontend (HTML/CSS/JS) — bundled *inside* the backend exe at build time (not shipped loose) |
| `build/` | Build scripts: `pack.js` (backend→exe), `make-tauri.js` (single-exe app), `make-zip.js` (customer zip), `publish.js` (auto-update), `make-ico.js` |
| `docs/` | Engineering reports, runbooks, audit ledger |
| `stress/` | Load-test harnesses (refresh / bulk-op stress, Steam libs mocked) |
| `website/` | Static web assets (license / landing pages) |
| `dist/` | Compiled backend JS — generated by `tsc`, gitignored |

**Gitignored / never commit:** `Vault/` (encrypted credentials), `secrets.local.bat` (license build
secrets), `data/`, `logs/`, `mafiles/`, `*.exe`, `release*/`, `src-tauri/target/`.

## Build
```
npm run build:tauri      # single-exe app -> release-tauri/SSIM/SSIM.exe (backend embedded inside it)
npm run build:protected  # backend only -> ssim-backend.exe (then embedded by build:tauri)
```
Requires `secrets.local.bat` (LICENSE_PEPPER / LICENSE_API_URL / LICENSE_PUBLIC_KEY) and the Rust
toolchain. If `rustup` reports "no toolchains", point `RUSTUP_HOME` / `CARGO_HOME` at your rustup
install before building. (The first Tauri build after clearing `src-tauri/target/` is a one-time
full compile.)

## Deliverables & auto-update
- **Fresh installs — customer zip:** `release/SSIM-<version>.zip` (clean: one SSIM.exe + README, no data/vault).
- **Existing customers — one-command publish:**
  ```
  npm run publish-update            # publish the current release-tauri/SSIM build
  npm run publish-update -- --build # build:tauri first, then publish
  ```
  Reads the version from `package.json`, logs into the license server, uploads the **single SSIM.exe**,
  and the server signs the manifest. New clients swap SSIM.exe (single-file). Needs `LICENSE_API_URL` +
  `SSIM_ADMIN_PASSWORD` in `secrets.local.bat`, and the license server running the updated code
  (`/admin/api/release/*` — deploy `ssim-license-server` once).
- **Existing two-file (v1.2.x) installs migrate automatically** on their next update: the published
  manifest lists SSIM.exe in `files[]`, so their *old* updater swaps this single exe in over the old
  shell; the new exe then cleans the orphaned `ssim-backend.exe`. From then on it is the simple
  single-file path (`Updater.ts`) — no dual-format in the client anymore.

## Run
Double-click `SSIM.exe`. It creates `data/`, `Vault/`, `logs/`, `mafiles/` next to itself on first run.

## Crash diagnostics (in `logs/`, next to the exe)
| File | What it tells you |
|---|---|
| `shell.log` | backend exit **code/signal** + dying stderr (shell-side — catches external kills) |
| `exit-trace.log` | present after a death = backend exited *itself* (the code names the path); **absent = external `TerminateProcess`** |
| `stderr-trace.log` | raw backend stderr last-words winston can't capture |
| `mem-heartbeat.log` | rss / heap / handles / live-session trajectory |
| `crash-log.txt` | JS-level uncaught throws / SIGHUP |
